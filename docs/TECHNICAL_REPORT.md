# Technical report: native tool use in PersonaPlex

## Objective

The project asks whether a full-duplex speech model can own the complete tool
trajectory instead of delegating intent recognition and response generation to
an external streaming pipeline. The target behavior is:

1. speech enters the causal audio state;
2. the model emits a typed native action;
3. a trusted executor performs an allow-listed operation;
4. its typed result enters the same continuing model state;
5. the model generates the spoken confirmation.

No ASR transcript or external planner decides whether to call the tool.

## Research framing

The architectural goal was inspired by
[`hyzhang24/DuplexSLA`](https://github.com/hyzhang24/DuplexSLA): synchronize
speech, language, and action on the duplex model's own clock instead of
relegating agentic behavior to a turn-boundary cascade. Because the published
DuplexSLA repository described a Step-Audio-2-mini-based model and listed its
inference artefacts as forthcoming, this work did not attempt to copy or claim
its implementation. It tested the principle independently on PersonaPlex.

That distinction shaped the engineering plan. A valid tool packet was not
enough: the result had to become visible to the same continuing speech-model
state, and the subsequent confirmation had to be generated by that model. The
full provenance and comparison are in [../ACKNOWLEDGMENTS.md](../ACKNOWLEDGMENTS.md).

## Architecture

PersonaPlex/Moshi is extended with two five-slot symbolic lanes synchronized to
its 12.5 Hz, 80 ms frame clock:

- the **action lane** is sampled from the model and carries calls, controls,
  references, tools, and arguments;
- the **environment lane** is authored by the trusted runtime and carries
  pending, success, error, timeout, cancellation, and stale-result events.

The runtime parser accepts only grammar-valid packets. Reference leases bind
executor events to the exact model call that created them. Environment events
are serialized through a causal FIFO and become visible only after their final
micro-position has entered the model state.

The host owns protocol authentication, schema validation, acoustic turn
bounding, and allow-listed execution. It does not own semantic call selection
or assistant wording.

## Training approach

The 7B PersonaPlex base is kept separate. Training updates compact lane modules
and selected adapter components, producing a 327,136,442-byte checkpoint.
Training examples align causal Mimi user codes, five-slot action targets,
executor observations, and result-grounded assistant audio/text.

The fundamental causality rule is that no assistant target grounded in a tool
result may begin before the terminal environment event becomes model-visible.
Dataset and runtime checks reject future-result leakage and malformed action or
environment frames.

The promoted v169 checkpoint is narrow and deliberately optimized for a frozen
two-minute timer trajectory. It is not evidence of broad semantic competence.

## Verified persistent result

Frozen input: `examples/timer-v169/input.wav`

Spoken content: “Count down two minutes for me.”

Measured Windows eager result:

| Measurement | Result |
| --- | --- |
| Frames | 46 |
| Native calls | 1 |
| Tool | `timer.create` |
| Arguments | `{"minutes":"MIN_2"}` |
| Call frame | 20 |
| Scheduled duration | 120 seconds |
| Terminal result | `OK` |
| Result visible frame | 25 |
| Generated text | `Sure, set a 2 minutes.` |
| Assistant audio RMS | 0.016331 |
| Assistant audio peak | 0.442787 |
| Real-time factor | 12.991 |

The result proves that the native lane emitted a valid call, the executor result
re-entered the same continuing state, and the model subsequently generated
finite text and audio. It does not prove that the response wording is polished
or that the behavior generalizes.

## What worked

- A five-slot typed protocol made model actions parseable without accepting
  arbitrary text as executable instructions.
- Grammar masking prevented structurally illegal packets.
- Reference leases and FIFO scheduling provided deterministic result causality.
- Lane-only checkpoints avoided duplicating the 16.7 GB base model.
- Causal WAV replay isolated model behavior from microphone and timing noise.
- Result-grounded training produced one complete call/result/response path.

## What did not work

- Earlier weather checkpoints repeated calls and emitted placeholder city
  tokens, showing memorized mechanics rather than reliable speech semantics.
- Several timer checkpoints called correctly but failed to speak the returned
  result, repeated the call, or produced unstable text/audio.
- A real USB-microphone attempt produced coherent speech but no action packet.
- A later microphone run was invalid because it never progressed past model
  loading.
- Python-level CUDA graph experiments changed the sampling trajectory and lost
  the successful call, text, or audio behavior.
- Native Windows PyTorch lacked Flash Attention support and remained far from
  real time.

Failed experiments are not treated as evidence for the promoted result.

## Limitations and next work

The current checkpoint is seed-pinned, vocabulary-limited, and validated on a
single controlled request. The next engineering gate is Linux eager parity with
the exact call/result/text/audio trajectory, followed by optimized attention,
saved-microphone replay, greeting-then-timer replay, no-tool negatives, and a
continuous live microphone session.

Broader usefulness requires multiple tools, argument diversity, difficult
negatives, interruptions, cancellations, executor errors, delayed results, and
held-out human speech. Safety evaluation must remain separate from packet
validity: a syntactically correct call can still be semantically wrong.

For the complete experiment sequence and the decisions produced by failed
attempts, see [DEVELOPMENT_TIMELINE.md](DEVELOPMENT_TIMELINE.md).
